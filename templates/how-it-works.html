Step 2 & 3

Feature engineering.

The raw dataset has 16 columns. After preprocessing, the model operates on 54 features — 13 original numeric fields, 5 newly engineered features, and 36 one-hot encoded columns from 8 categorical variables.

Original

Age (mapped)

Age ranges converted to midpoint numerics: [60-70) → 65. Enables ordinal relationship for linear models.

Original

Time in Hospital

Days admitted. Longer stays correlate with severity. Also used as denominator for meds-per-day.

Original

n_medications

Count of medications prescribed. High counts (≥5) trigger polypharmacy flag. Strong predictor of complexity.

Engineered

total_visits

n_inpatient + n_outpatient + n_emergency. Summarises overall healthcare utilisation in a single signal.

Engineered

visit_severity

3×inpatient + 2×emergency + 1×outpatient. Weighted score reflecting acuity of prior healthcare interactions.

Engineered

polypharmacy

Binary flag (1 if n_medications ≥ 5). Polypharmacy is clinically significant and linked to higher readmission rates.

Engineered

meds_per_day

n_medications / time_in_hospital. Captures treatment intensity relative to stay duration.

Engineered

long_stay

Binary flag (1 if time_in_hospital > 7 days). Prolonged stays indicate medical complexity and higher risk.

One-Hot

Categorical columns (×8)

medical_specialty, diag_1/2/3, glucose_test, A1Ctest, change, diabetes_med — expanded to 36 binary columns.

Step 5

Three models, one decision.

Each model brings a different strength. Logistic Regression is fast and interpretable. Random Forest captures complex non-linear patterns. XGBoost uses sequential boosting to reduce prediction error. Together, they outperform any single model.

Logistic Regression

Linear baseline

Draws a decision boundary by fitting a sigmoid function to the data. Despite its simplicity, it provides an interpretable baseline and captures linear relationships between features and readmission.

Ensemble weight:
1×

Random Forest

Bagging ensemble

Builds 250 independent decision trees, each trained on a random subset of features and samples. Majority vote across trees reduces variance and handles non-linear feature interactions well.

Ensemble weight:
1×

XGBoost

Gradient boosting

Builds trees sequentially — each new tree focuses on correcting the residual errors of the previous one. Regularisation (gamma, alpha, lambda) prevents overfitting. Given double weight in the ensemble due to superior recall.

Ensemble weight:
2×
Soft Voting — How Probabilities Are Combined
LR → P(readmit) = 0.51 weight 1
RF → P(readmit) = 0.44 weight 1
XGB → P(readmit) = 0.48 weight 2

Weighted Average

(0.51×1 + 0.44×1 + 0.48×2) ÷ 4

= 0.4775

vs Threshold 0.42

0.4775 ≥ 0.42

→ Predict Readmitted

Step 6

Threshold tuning.

Why 0.42 and not 0.50?

By default, a classifier predicts "readmitted" if the probability exceeds 0.50. But 0.50 is arbitrary — it was never calibrated to the clinical cost of being wrong.

In healthcare, a false negative — predicting a high-risk patient as safe — is far more dangerous than a false positive. A missed high-risk patient may deteriorate and return in a worse condition, often to the ICU.

We evaluated every threshold from 0.30 to 0.70 in 0.01 steps on the validation set, measuring recall and accuracy at each point. At threshold = 0.42, recall on the readmitted class jumped to 75% while accuracy stayed around 60% — an acceptable clinical trade-off.

Key insight: Lowering the threshold doesn't change the model — it changes the decision rule. The model still outputs the same probabilities. You're just saying "flag anyone above 42% as high-risk" instead of 50%.
